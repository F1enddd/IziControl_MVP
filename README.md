# AI-анализ переговоров с клиентами

MVP для автоматизированного анализа переговоров менеджеров B2B-интегратора.

Система принимает расшифровку разговора с клиентом, передаёт её в YandexGPT и формирует структурированный результат анализа.

## Что анализируется

Для каждого разговора система определяет:

* итог разговора;
* следующий согласованный шаг;
* дату следующего действия;
* потребности клиента;
* ключевые риски;
* ошибки менеджера;
* вопросы, требующие внимания менеджера.

При анализе запрещено придумывать отсутствующие в разговоре факты и конкретные даты.

## Валидация

Одной инструкции для LLM недостаточно, поэтому часть критических проверок вынесена в Python.

В текущем MVP проверяются:

1. наличие обязательных полей;
2. соответствие результата ожидаемой JSON-структуре;
3. формат даты `YYYY-MM-DD`;
4. соответствие конкретной даты содержанию разговора;
5. корректная обработка относительных дат;
6. отсутствие выдуманной точной даты там, где в разговоре указан только диапазон или условие.

Например:

```text
"после 20 января"
```

не может автоматически превратиться в:

```text
2027-01-20
```

В таком случае `next_action_date` должен быть `null`.

Если результат не проходит проверку, система отправляет модели результат и описание найденной ошибки и запрашивает исправленную версию. После этого результат проверяется повторно.

## Что было проверено

MVP протестирован на 4 предоставленных транскриптах.

В ходе тестирования проверялись:

* корректное извлечение следующего шага;
* вычисление относительных дат (`завтра`, `в четверг`, `в пятницу`);
* отсутствие даты при недостаточно точной договорённости;
* корректное определение потребностей и рисков;
* выявление конкретных ошибок менеджера;
* работа механизма retry.

### Пример обнаруженной ошибки

На одном из тестовых разговоров модель указала конкретную дату действия, хотя из разговора следовало только условие/относительный срок.

Python-валидатор обнаружил несоответствие:

```text
VALIDATION ERRORS:
- Дата результата не соответствует датам,
  которые можно вывести из разговора.
```

После этого был выполнен retry с описанием ошибки.

Повторный результат прошёл валидацию:

```text
VALIDATION: OK AFTER RETRY
```

Таким образом, ошибка модели не остаётся незамеченной и проходит дополнительную проверку перед сохранением результата.

## Формат результата

### JSON

Каждый разговор сохраняется в отдельный файл:

```text
output/json/transcript_1.json
```

Пример структуры:

```json
{
  "outcome": "...",
  "next_step": "...",
  "next_action_date": "2026-09-10",
  "client_needs": [],
  "risks": [],
  "manager_mistakes": [],
  "manager_attention": []
}
```

### Excel

Для каждого разговора также создаётся отдельный Excel-файл:

```text
output/excel/transcript_1.xlsx
```

Он содержит те же данные в удобном для менеджера формате.

## Запуск

Установить зависимости:

```bash
pip install requests python-dotenv pydantic openpyxl
```

Создать `.env`:

```env
YANDEX_API_KEY=your_api_key
YANDEX_FOLDER_ID=your_folder_id
```

Запустить:

```bash
python main.py
```

После выполнения результаты появятся в:

```text
output/json/
output/excel/
```
